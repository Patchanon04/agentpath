# agentpath

เรียนรู้ว่า AI agent ทำงานอย่างไรจริง ๆ ด้วยการลงมือสร้างมันขึ้นมาเอง ตั้งแต่การเรียก
LLM เพียงครั้งเดียว ไปจนถึง agent harness ที่สมบูรณ์

## เหมาะกับใคร

คุณเขียนโปรแกรมได้บ้าง แต่ยังไม่เคยสร้างอะไรด้วย language model มาก่อน หรือเคยใช้ผ่าน
framework แล้วไม่เคยเข้าใจว่าข้างใต้มันทำอะไรอยู่ คุณไม่จำเป็นต้องรู้ machine learning เลย
24 บทเรียนไม่มีคณิตศาสตร์ สองภาคเสริมที่ขนาบอยู่คือที่ที่ตัวเลขอาศัยอยู่ และข้ามได้ทั้งคู่

## ทำไมถึงมีคอร์สนี้

มีบทเรียนมากมายที่พาคุณดู agent loop แต่เกือบทั้งหมดหยุดอยู่แค่นั้น เครื่องมือที่คนใช้งานจริง
ทุกวันอย่าง Claude Code และ OpenHands ไม่ใช่แค่ agent loop มันคือ harness ซึ่งหมายถึง
agent loop ที่ถูกห้อมล้อมด้วยการตรวจสอบสิทธิ์ การบันทึก session การจัดการ context การกู้คืน
จากข้อผิดพลาด และ protocol สำหรับ plugin แทบไม่มีใครสอนให้คุณสร้างส่วนนั้น

คอร์สนี้พาไปจนสุดทาง คุณเริ่มจากการส่ง HTTP request หนึ่งครั้งไปหา model และจบด้วย harness
ที่คุณเอาไปใช้งานได้จริง

ทุกบทยังมีฉบับภาษาไทยด้วย ซึ่งหาได้ยากมากสำหรับเนื้อหาที่ลงลึกขนาดนี้

และให้บริการ model ของตัวเอง ห้าบท คือการจัดการข้อมูล LoRA quantization การปรับตาม

trl ที่ต้องมี GPU ส่วนบทข้อมูลกับบทให้บริการเป็น Python ล้วนทั้งสองชั้น อยู่ที่
[training/](training/)

## เริ่มต้นอย่างรวดเร็ว

ติดตั้ง uv ซึ่งเป็นตัวติดตั้ง Python และตัวจัดการ environment ที่คอร์สนี้ใช้

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

บน Windows ให้ใช้ PowerShell แทน

```powershell
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
```

จากนั้น clone repository แล้วเปิดบทแรก

```bash
git clone https://github.com/Patchanon04/agentpath.git
cd agentpath
```

ตอนนี้ให้อ่าน [lessons/00-setup/README.md](lessons/00-setup/README.md) มันจะพาคุณเลือกว่าจะ
ให้ model ของคุณรันที่ไหน ซึ่งจะเป็นแบบฟรีและรันในเครื่องก็ได้ถ้าคุณต้องการ และตั้งค่า
environment variable สามตัวที่ทุกบทใช้เพื่อเรียกถึง model

## การใช้ framework ฉบับสมบูรณ์

ทุกอย่างที่คอร์สนี้สร้างขึ้นถูกเผยแพร่เป็น package ด้วย คุณจึงติดตั้งฉบับสมบูรณ์แล้วอ่านเป็น
เอกสารอ้างอิงได้

```bash
pip install agentpath-kit
```

ชื่อที่ใช้ติดตั้งคือ `agentpath-kit` แต่ชื่อ package ที่ได้มาคือ `agentpath` คุณจึงติดตั้งชื่อหนึ่ง
แล้ว import อีกชื่อหนึ่ง ตรงนี้ไม่ได้พิมพ์ผิด PyPI ปฏิเสธชื่อเปล่าๆ เพราะมี package ร้างชื่อ
`agent_path` ที่ใกล้กันมากพอจะทำให้สับสน และการแยกสองชื่อออกจากกันคือคำตอบปกติของ
Python แบบเดียวกับที่คุณติดตั้ง `scikit-learn` แล้ว import `sklearn` ถ้าติดตั้ง `agentpath`
เฉยๆ คุณจะได้ template เปล่าของคนอื่น เครื่องหมายขีดจึงสำคัญ

```bash
export AGENTPATH_BASE_URL=http://localhost:11434/v1
export AGENTPATH_MODEL=qwen3
agentpath chat
```

ตอนนี้คำสั่งนี้มีคำสั่งย่อยสี่ตัว `chat` คือ session แบบโต้ตอบ `run` ทำงานหนึ่งงานแล้วจบ
`resume` ทำงานต่อจาก session ที่คุณบันทึกไว้ก่อนหน้า และ `eval` รันไฟล์ของงานแล้วรายงานว่างานไหน
ผ่านบ้าง คุณเชื่อมต่อ MCP server ได้ด้วย `--mcp` เพื่อให้ agent ใช้ tool ที่คุณไม่ได้เขียนเองได้

### การใช้มันเป็น library

บรรทัดคำสั่งเป็นแค่ผู้เรียกหนึ่งรายในหลายราย `run` เป็น generator ที่ yield event ออกมาตามที่มัน
เกิดขึ้น loop ข้างล่างจึงคือการเชื่อมต่อทั้งหมด

```python
import os

from agentpath import Agent, OpenAICompatProvider, TextDelta, TurnDone, file_tools
from agentpath.tools.base import ToolRegistry

agent = Agent(
    provider=OpenAICompatProvider(),
    tools=ToolRegistry(file_tools(os.getcwd())),
)

for event in agent.run("Summarise what this project does, in two sentences."):
    if isinstance(event, TextDelta):
        print(event.text, end="", flush=True)
    elif isinstance(event, TurnDone):
        print()
```

`agent.run` yield event สี่ชนิด `TextDelta` คือชิ้นส่วนของคำตอบตอนที่มันทยอยมาถึง
`ToolCallRequest` บอกว่ากำลังจะรัน tool `ToolResult` คือสิ่งที่ tool คืนกลับมา และ `TurnDone`
แปลว่าจบรอบแล้ว การเพิกเฉยต่อ event ที่คุณไม่สนใจเป็นเรื่องปกติ ซึ่งเป็นเหตุผลที่ loop ข้างบน
เรียกชื่อแค่สองตัว

`Agent` ที่สร้างโดยไม่ส่ง `permissions` จะอนุมัติทุก tool call และ `file_tools` มี `write_file`
กับ `edit_file` อยู่ด้วย ให้ชี้ตัวอย่างนี้ไปที่โฟลเดอร์ที่คุณไม่ห่วงว่าจะถูกแก้ หรือส่ง
`Permissions(ask=ask_in_terminal)` เพื่อให้ถามก่อน

ทุกอย่างข้างบน import จาก module ที่มันอยู่จริงได้ด้วย และพาธที่ลึกกว่าคืออันที่อ่านแล้วได้ประโยชน์
มากกว่า `from agentpath.tools.base import ToolRegistry` บอกคุณว่าของอยู่ที่ไหน และบทเรียน
สร้างโครงสร้างนั้นตามลำดับนี้ด้วยเหตุผล

## หนังสือ

บทเรียนสอนให้คุณสร้าง ยังมีหนังสือที่อธิบายว่าทำไมมันถึงถูกสร้างแบบนั้น และจะคิดอย่างไรเมื่อ
คุณอยากออกแบบของตัวเอง หนังสือเขียนเป็นภาษาไทย โดยคงศัพท์เทคนิคไว้เป็นภาษาอังกฤษ

[book/](book/) มียี่สิบแปดบทในห้าภาค นับตั้งแต่ภาค 0 ถึงภาค 4 ภาค 0 คือบทพื้นฐานเจ็ดบท
ตั้งแต่ข้อความเป็น byte จนถึง chat template แต่ละบทมีโฟลเดอร์โค้ดใน `foundations/` ภาค 1
คือทฤษฎีเจ็ดบทที่อยู่เบื้องหลังคอร์ส ภาค 2 คือสี่บทว่าด้วยการเอาไอเดียมาคิดว่าจะสร้างอะไร
พร้อมกรณีศึกษายาวเรื่อง LINE ผู้ช่วยสุขภาพ และอีกสามกรณีสั้นที่ได้คำตอบต่างกัน ภาค 3 คือ
ห้าบทที่ไล่อ่านโค้ดฉบับสมบูรณ์ใน `src/agentpath/` ทีละชิ้น ภาค 4 คือห้าบทว่าด้วยการ
fine-tune และให้บริการ model ของตัวเอง แต่ละบทมีโฟลเดอร์โค้ดใน `training/`

## โครงสร้างของ repository นี้

`lessons/` เก็บโฟลเดอร์หนึ่งโฟลเดอร์ต่อหนึ่งบท แต่ละโฟลเดอร์อยู่ได้ด้วยตัวเอง คุณจึงเปิดบทไหน
ก็ได้แล้วรันโค้ดของมันโดยไม่ต้องทำบทอื่นมาก่อน โค้ดถูกทำซ้ำระหว่างบทอย่างตั้งใจ เพราะคอร์สที่
บทสี่แอบไปขึ้นอยู่กับการแก้ไขที่คุณทำในบทสอง คือคอร์สที่คนเลิกเรียนกลางคัน

`foundations/` เก็บโค้ดเจ็ดโฟลเดอร์สำหรับคนที่ยังไม่รู้ว่า token คืออะไร มันมาก่อนบทเรียนที่ 01
และไม่ต้องใช้ API key ข้อความเป็น byte tokenizer จากศูนย์ language model ที่นับ ตัวที่
เรียนรู้ vector ของคำ attention บนสี่ token และ chat template แต่ละโฟลเดอร์มี README
สั้นๆ สองภาษา ส่วนบทเต็มอยู่ในหนังสือเป็นภาษาไทย ที่นี่กับภาคฝึกคือสองที่ในคอร์สที่ใช้ numpy

`training/` เก็บห้าโฟลเดอร์ของภาค 4 ของหนังสือ คือการ fine-tune และให้บริการ แต่ละโฟลเดอร์
มี check ที่ CI รัน LoRA quantization และ DPO ยังมีโค้ด numpy บนตารางเดียวกับที่ภาคพื้นฐาน
ฝึก และ script จริงที่ต้องมี GPU กับ extra ชื่อ `training` ซึ่ง CI ไม่รัน ส่วนการล้างข้อมูล
กับเลขคณิตที่บอกว่าการ์ดใบหนึ่งให้บริการอะไรได้เป็น Python ล้วน ไม่ต้องมี GPU ทั้งสองชั้น

`src/agentpath/` เก็บ framework ฉบับสมบูรณ์ ซึ่งก็คือแนวคิดเดียวกันที่เขียนไว้ครั้งเดียว
อย่างเรียบร้อย พร้อมชุดทดสอบ

`ci/` เก็บสคริปต์ที่รันการตรวจสอบของทุกบท และสคริปต์ตรวจสไตล์งานเขียน
ส่วน model server จำลองที่มันรันด้วยอยู่ใน `src/agentpath/testing/`

`docs/` เก็บเอกสารออกแบบ แผนการพัฒนา และไอเดียหัวข้อที่เก็บไว้สำหรับเวอร์ชันสอง

## การรันการตรวจสอบด้วยตัวเอง

ทุกบทมีไฟล์ check.py ที่พิสูจน์ว่าโค้ดที่คุณเขียนทำงานได้จริง คุณรันทั้งหมดพร้อมกันกับ model
server จำลองได้ ซึ่งไม่มีค่าใช้จ่ายและไม่ต้องใช้ API key

```bash
uv pip install -e ".[dev,foundations]"
python ci/run_lessons.py
```

extra ชื่อ `foundations` คือ numpy ซึ่ง check ของภาคพื้นฐานและภาคฝึก model ต้อง import
ส่วน check ของ 24 บทเรียนต้องการแค่ httpx นี่คือสคริปต์ตัวเดียวกันและบรรทัดติดตั้งเดียวกับ
ที่โปรเจกต์รันใน continuous integration ถ้ามันผ่านสำหรับคุณ มันก็ผ่านสำหรับทุกคน

## การร่วมพัฒนา

ยินดีรับ issue และ pull request มีกฎสองข้อที่สำคัญกว่าข้ออื่น

คอร์สนี้ถูกตรึงไว้ที่ 24 บท ไอเดียหัวข้อใหม่ควรไปอยู่ใน [docs/v2-ideas.md](docs/v2-ideas.md)
ไม่ใช่ในบทใหม่ ถ้าคุณอยากเพิ่มบท คุณต้องหาเหตุผลมาสนับสนุนว่าจะตัดบทไหนออก สองภาคที่ขนาบ
คอร์สถูกตรึงด้วยกฎเดียวกัน ภาคพื้นฐานที่เจ็ดบทเพราะมันอยู่ก่อนบทเรียนที่ 01 และภาคฝึก model
ที่ห้าบทเพราะมันอยู่หลังบทเรียนที่ 23 และสอนคนละเรื่อง คือตัว model ไม่ใช่ harness

งานเขียนมีสไตล์ประจำบ้าน ห้ามใช้ em dash ห้ามใช้ emoji และห้ามใช้เครื่องหมายทวิภาคในประโยค
ทั่วไป มีการตรวจสอบใน continuous integration ที่บังคับใช้ทั้งสามข้อ โดยผ่อนกฎเรื่องทวิภาค
ให้เฉพาะบันทึกการทำงานใน `docs/plans/` และ `docs/specs/`
