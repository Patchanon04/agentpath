# บทที่ 19 quantization พร้อมวัดความผิดที่จ่าย

คุณกดเช่าการ์ดแปดสิบกิกะไบต์รายชั่วโมงไว้แล้ว พิมพ์คำสั่งโหลด model
แล้วนั่งรอสองนาที สิ่งที่ได้กลับมาคือบรรทัดเดียวที่บอกว่าหน่วยความจำไม่พอ ขาดอีก
ห้าสิบห้ากิกะไบต์ และมิเตอร์ค่าเช่าเดินอยู่ตลอดเวลาที่คุณนั่งอ่านบรรทัดนั้น

model เจ็ดหมื่นสองพันล้าน parameter ที่สิบหกบิตต่อตัวเลขคือร้อยสามสิบห้ากิกะไบต์ ไม่มีการ์ด
แปดสิบกิกะไบต์ใบไหนรับได้ และคนที่จะให้บริการมันมีสองทาง ต่อการ์ดสองใบ หรือทำให้ตัวเลข
แต่ละตัวเล็กลง ทางที่สองคือบทนี้ และคำถามเดียวของมันคือเล็กลงแล้วเสียอะไร

ตารางของบทพื้นฐานที่ 4 ตอบได้ เก็บที่แปดบิตแทนหกสิบสี่ ไฟล์เล็กลงเจ็ดเท่า loss ไม่ขยับ
ในทศนิยมตำแหน่งที่สี่ เก็บที่สี่บิต เล็กลงอีกครึ่ง และ loss ขยับหกในพัน แถวแรกคือของฟรีที่
แท้จริง แถวที่สองคือการแลกจริง และมันเป็นตัวเลข ไม่ใช่ความรู้สึก model ที่คุณเรียกผ่าน API
ถูกเก็บแบบใดแบบหนึ่งในสองแบบนี้เกือบทั้งหมด และบทที่ 21 จะให้เห็นว่าทำไมจำนวนไบต์ต่อตัว
เลข คือสิ่งที่ตัดสินทั้งหน่วยความจำและความเร็ว

## 1. ตัวเลขหนึ่งตัวใช้กี่ไบต์ และทำไมถึงลดได้

ตัวเลขใน model ตอนฝึกคือทศนิยมสิบหกหรือสามสิบสองบิต ช่วงกว้าง ความละเอียดสูง ซึ่งการ
ฝึกต้องการ เพราะ gradient ในบทที่ 4 คือค่าเล็กมากที่สะสมทีละน้อย แต่หลังฝึกเสร็จ ตัวเลขไม่
ขยับอีก และสิ่งเดียวที่มันทำคือถูกคูณ คำถามคือมันต้องแม่นแค่ไหนถึงจะคูณแล้วได้คำตอบเดิม

quantization (เก็บตัวเลขด้วยบิตน้อยลง แล้วใช้ตัวคูณคืนช่วงเดิม)
ตอบว่าไม่ต้องแม่นเท่าที่คิด ทศนิยมสิบหกบิตแทนค่าได้หลายหมื่นระดับ จำนวนเต็มแปดบิตแทน
ได้สองร้อยห้าสิบห้า และ model ทนความหยาบนั้นได้เพราะข้อผิดพลาดของตัวเลขแต่ละตัวเล็ก สุ่ม
และหักล้างกันเองเมื่อรวมเป็นพัน

นึกภาพแถวเดียวที่มีตัวเลขสี่พันตัว การปัดเศษเลื่อนแต่ละตัวไปไม่เกินครึ่งขั้น บางตัวขึ้น บาง
ตัวลง พอบวกผลคูณสี่พันชิ้นเข้าด้วยกัน ส่วนที่ขึ้นกับส่วนที่ลงล้างกันเกือบหมด ผลรวมจึงเพี้ยน
น้อยกว่าครึ่งขั้นคูณสี่พันมาก

## 2. absmax คือปัดเศษด้วยไม้บรรทัดของแต่ละแถว

วิธีที่ง่ายที่สุดที่ยังใช้งานได้จริงมีชื่อว่า absmax (ใช้ตัวเลขที่ใหญ่สุดในกลุ่มมากำหนดตั
วคูณ) และมันคือหกบรรทัด

```python
def quantize(grid, bits=8):
    """Round each row to integers of the given width, with one scale per row."""
    levels = 2 ** (bits - 1) - 1
    scale = np.abs(grid).max(axis=1, keepdims=True) / levels
    scale[scale == 0] = 1.0
    integers = np.round(grid / scale).astype(np.int64)
    return integers, scale
```

หาตัวเลขที่ใหญ่ที่สุดในแถว ให้มันเป็นจำนวนเต็มที่ใหญ่ที่สุดที่บิตนั้นแทนได้ ร้อยยี่สิบเจ็ด
สำหรับแปดบิต เจ็ดสำหรับสี่บิต ตัวเลขอื่นทุกตัวในแถวถูกหารด้วยไม้บรรทัดเดียวกันแล้วปัดเป็น
จำนวนเต็ม สิ่งที่เก็บคือจำนวนเต็มทั้งแถวกับไม้บรรทัดหนึ่งอัน และตอนใช้งานคูณกลับ

```python
def dequantize(integers, scale):
    """Back to real numbers, which is what happens on the way into every matrix multiply."""
    return integers * scale
```

ไม้บรรทัดต่อแถวแทนที่จะต่อทั้งตาราง เพราะแถวที่มีตัวเลขเล็กข้างแถวที่มีตัวเลขใหญ่ จะเสียราย
ละเอียดทั้งหมดให้ไม้บรรทัดของแถวใหญ่

## 3. ตารางที่วัดได้

```text
a grid of 1156 numbers, loss 0.7868 at 64 bits each

bits   bytes   loss     what changed
  64    9248   0.7868   nothing, this is the model
   8    1292   0.7868   one scale per row
   4     714   0.7930   one scale per row
   4     850   0.7898   one scale per group of 17
```

แปดบิตฟรี ไบต์ลดเจ็ดเท่า loss ไม่ขยับในทศนิยมตำแหน่งที่สี่ นี่คือเหตุผลที่ผู้ให้บริการส่วน
ใหญ่ลดจากสิบหกบิตทันทีที่การ์ดรองรับ

สี่บิตไม่ฟรี ไม้บรรทัดต่อแถวลดไบต์อีกครึ่งและมีราคาหกในพันของ loss บนตารางนี้ยังใช้ได้
บน model จริงมักไม่ และแถวสุดท้ายคือทางแก้ที่รูปแบบไฟล์สี่บิตทุกตัวใช้

## 4. ไม้บรรทัดต่อกลุ่ม คือสิ่งที่รูปแบบไฟล์ต่างกัน

ที่สี่บิตมีระดับให้ใช้แค่สิบห้า ไม้บรรทัดต่อแถวใช้ระดับส่วนใหญ่ไปกับตัวเลขใหญ่ไม่กี่ตัว และ
ตัวเลขเล็กที่เหลือทั้งแถวถูกปัดไปที่ศูนย์หรือหนึ่ง ดูสองบรรทัดสุดท้ายของการรัน

```text
the largest single error at 4 bits with a scale per row is 0.460
the largest number in the grid is 8.938
```

ตัวเลขใหญ่สุด 8.9 กำหนดขั้นของไม้บรรทัดที่ 1.3 ตัวเลขที่เล็กกว่า 0.6 ทั้งแถวกลายเป็นศูนย์
ไม้บรรทัดต่อกลุ่มเล็กๆ แก้ด้วยการให้แต่ละกลุ่มมีขั้นของตัวเอง

```python
def quantize_grouped(grid, bits=4, group=17):
    """Four bit with a scale per small group, which is what the GGUF and GPTQ families do."""
    flat = grid.reshape(-1, group)
    integers, scale = quantize(flat, bits)
    return integers.reshape(grid.shape), scale
```

ราคาคือไม้บรรทัดมากขึ้น ในตารางคือร้อยสามสิบหกไบต์ ผลคือ loss ลงจากหกในพันเหลือสามในพัน

นี่คือปุ่มที่รูปแบบไฟล์ต่างกัน GGUF ที่ llama.cpp ใช้มีหลายความกว้าง ตั้งแต่สองถึงแปดบิต
ส่วน GPTQ กับ AWQ ที่ vLLM ใช้คือสี่บิตกับไม้บรรทัดต่อกลุ่มร้อยยี่สิบแปดเป็นค่าปกติ ต่างกัน
ที่วิธีเลือกไม้บรรทัด บางตัวดูข้อมูลจริงที่ไหลผ่านตอนเลือกเพื่อรักษาตัวเลขที่สำคัญ และ nf4
(normal float สี่บิต คือวางสิบหกระดับตามการกระจายของ weight ที่ฝึกแล้ว) ที่
QLoRA ใช้วางสิบหกระดับไว้ตรงที่ตัวเลขของ model จริงกระจุกตัว แทนที่จะวางห่างเท่ากัน และ
ใช้กลุ่มหกสิบสี่ คุณไม่ต้องรู้รายละเอียดของแต่ละตัว สิ่งที่ต้องรู้คือคำถามเดียวที่ทุกตัวตอบ
ไม้บรรทัดกี่อัน วางยังไง

ความรู้นี้ใช้ตอนเลือกไฟล์จะโหลด หน้าหนึ่งของ model แบบเปิดมีไฟล์ชื่อลงท้ายว่า Q8_0 กับ
Q4_K_M วางเรียงกัน ตัวแรกคือแปดบิตในหัวข้อที่ 3 ใหญ่กว่าเท่าตัวและแทบไม่เสียอะไร ตัวหลัง
คือสี่บิตกับไม้บรรทัดต่อกลุ่มในหัวข้อนี้ และมันคือตัวที่คนโหลดกันมากที่สุด

## 5. QLoRA คือบทที่ 18 บนฐานที่ปัดเศษแล้ว

บทที่ 18 บอกว่า LoRA
ตรึงตารางเดิมและฝึกแค่คู่ตารางบาง ถ้าตารางเดิมถูกตรึงอยู่แล้ว มันไม่ต้องแม่นพอสำ
หรับ gradient ที่จะไหลเข้าไปในตัวมัน มันต้องแม่นพอแค่จะคูณ ซึ่งคือหัวข้อที่ 1
ผลคือเก็บฐานที่สี่บิต ฝึก adapter ที่สิบหกบิต และ model เจ็ดพันล้าน parameter
ที่ต้องการการ์ดราวยี่สิบกิกะไบต์สำหรับ LoRA ธรรมดา เหลือไม่ถึงสิบ

ตัวเลขนั้นเปลี่ยนว่าใครฝึกได้ ยี่สิบกิกะไบต์แปลว่าต้องเช่าเครื่องรายชั่วโมง ไม่ถึงสิบแปลว่า
การ์ดสำหรับเล่นเกมที่มีสิบสองกิกะไบต์ ซึ่งอยู่ใต้โต๊ะอยู่แล้ว ฝึก adapter ของบทที่ 18 จบได้
ในคืนเดียวโดยไม่ต้องจ่ายใครเพิ่ม

วิธีนี้ชื่อ QLoRA (quantized LoRA คือฝึก LoRA adapter บน model ฐานที่เก็บไว้ที่สี่บิต) และ
`load_4bit.py` ในโฟลเดอร์เดียวกันทำมัน โหลด model ด้วย nf4 รายงานหน่วยความจำเทียบกับ
สิบหกบิต และด้วย `--train` ใส่ adapter จากบทที่ 18 ซ้อนข้างบน บรรทัดเดียวที่ต่างจาก script
ของบทที่ 18 นอกจากการโหลดคือ `prepare_model_for_kbit_training` มันตรึงฐานสี่บิต ยกชั้นที่
ไม่ได้ถูกปัดเศษ คือ layer norm จากบทพื้นฐานที่ 6 กับตารางที่แปลง token สุดท้ายเป็นคะแนน
ไปไว้ที่ความละเอียดเต็มเพื่อความเสถียรของตัวเลข และเปิด gradient checkpointing เพื่อ
ประหยัดหน่วยความจำของ activation เพิ่มอีกชั้น

ต้องมี GPU ของ NVIDIA และ library bitsandbytes ซึ่งบน Windows ยังติดตั้งยากกว่า Linux และ
ไม่ได้รันใน CI สิ่งที่ CI รันคือตารางในหัวข้อที่ 3 ซึ่งคือกลไกเดียวกันบนของที่นับได้ครับ

## 6. สรุป

- หลังฝึกเสร็จตัวเลขแค่ถูกคูณ และการคูณทนความหยาบได้

- absmax คือไม้บรรทัดต่อแถว แปดบิตฟรี สี่บิตมีราคาที่วัดได้

- ไม้บรรทัดต่อกลุ่มคือสิ่งที่รูปแบบไฟล์สี่บิตทุกตัวทำ และต่างกันแค่วิธีเลือกไม้บรรทัด

- QLoRA คือ LoRA บนฐานสี่บิต เพราะฐานที่ตรึงไว้ไม่ต้องแม่นพอสำหรับ gradient
