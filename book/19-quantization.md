# บทที่ 19 quantization พร้อมวัดความผิดที่จ่าย

ตารางเดียวกัน เก็บสามแบบ หกสิบสี่บิตต่อตัวเลข เก้าพันสองร้อยไบต์ loss 0.7868 แปดบิตต่อ
ตัวเลข พันสองร้อยไบต์ loss 0.7868 สี่บิต เจ็ดร้อยไบต์ loss 0.7930 แถวกลางคือของฟรีที่แท้จริง
เล็กลงเจ็ดเท่าโดยไม่เสียอะไรที่วัดได้ แถวล่างคือการแลกจริง และมันเป็นตัวเลข ไม่ใช่ความรู้สึก

model ที่คุณเรียกผ่าน API ถูกเก็บแบบแถวกลางหรือแถวล่างเกือบทั้งหมด และบทที่ 21 จะให้เห็นว่า
ทำไมจำนวนไบต์ต่อตัวเลขคือสิ่งที่ตัดสินทั้งหน่วยความจำและความเร็ว บทนี้ทำสิ่งเดียว ปัดเศษ
ตารางของบทพื้นฐานที่ 4 แล้ววัด เพื่อให้คำว่า quantization เลิกเป็นคำ

## 1. ตัวเลขหนึ่งตัวใช้กี่ไบต์ และทำไมถึงลดได้

ตัวเลขใน model ตอนฝึกคือทศนิยมสิบหกหรือสามสิบสองบิต ช่วงกว้าง ความละเอียดสูง ซึ่งการ
ฝึกต้องการ เพราะ gradient ในบทที่ 4 คือค่าเล็กมากที่สะสมทีละน้อย แต่หลังฝึกเสร็จ ตัวเลขไม่
ขยับอีก และสิ่งเดียวที่มันทำคือถูกคูณ คำถามคือมันต้องแม่นแค่ไหนถึงจะคูณแล้วได้คำตอบเดิม

quantization (การลดความละเอียด คือการเก็บตัวเลขด้วยบิตน้อยลง โดยมีตัวคูณช่วยคืนช่วงเดิม)
ตอบว่าไม่ต้องแม่นเท่าที่คิด ทศนิยมสิบหกบิตแทนค่าได้หลายหมื่นระดับ จำนวนเต็มแปดบิตแทน
ได้สองร้อยห้าสิบห้า และ model ทนความหยาบนั้นได้เพราะข้อผิดพลาดของตัวเลขแต่ละตัวเล็ก สุ่ม
และหักล้างกันเองเมื่อรวมเป็นพัน

## 2. absmax คือปัดเศษด้วยไม้บรรทัดของแต่ละแถว

```python
def quantize(grid, bits=8):
    """Round each row to integers of the given width, with one scale per row."""
    levels = 2 ** (bits - 1) - 1
    scale = np.abs(grid).max(axis=1, keepdims=True) / levels
    scale[scale == 0] = 1.0
    integers = np.round(grid / scale).astype(np.int64)
    return integers, scale
```

หาตัวเลขที่ใหญ่ที่สุดในแถว ให้มันเป็นจำนวนเต็มที่ใหญ่ที่สุดที่บิตนั้นแทนได้ ร้อยยี่สิบเจ็ด
สำหรับแปดบิต เจ็ดสำหรับสี่บิต ตัวเลขอื่นทุกตัวในแถวถูกหารด้วยไม้บรรทัดเดียวกันแล้วปัดเป็น
จำนวนเต็ม สิ่งที่เก็บคือจำนวนเต็มทั้งแถวกับไม้บรรทัดหนึ่งอัน และตอนใช้งานคูณกลับ

```python
def dequantize(integers, scale):
    """Back to real numbers, which is what happens on the way into every matrix multiply."""
    return integers * scale
```

ไม้บรรทัดต่อแถวแทนที่จะต่อทั้งตาราง เพราะแถวที่มีตัวเลขเล็กข้างแถวที่มีตัวเลขใหญ่จะเสียราย
ละเอียดทั้งหมดให้ไม้บรรทัดของแถวใหญ่ วิธีนี้ชื่อ absmax (ค่าสัมบูรณ์สูงสุด คือการใช้ตัวเลขที่
ใหญ่ที่สุดในกลุ่มกำหนดตัวคูณ) และมันคือรูปที่ง่ายที่สุดที่ยังใช้งานได้จริง

## 3. ตารางที่วัดได้

```text
a grid of 1156 numbers, loss 0.7868 at 64 bits each

bits   bytes   loss     what changed
  64    9248   0.7868   nothing, this is the model
   8    1292   0.7868   one scale per row
   4     714   0.7930   one scale per row
   4     850   0.7898   one scale per group of 17
```

แปดบิตฟรี ไบต์ลดเจ็ดเท่า loss ไม่ขยับในทศนิยมตำแหน่งที่สี่ นี่คือเหตุผลที่การให้บริการทุก
ที่เริ่มจากแปดบิต และเหตุผลที่ไม่มีใครให้บริการ model ที่สิบหกบิตถ้าเลี่ยงได้

สี่บิตไม่ฟรี ไม้บรรทัดต่อแถวลดไบต์อีกครึ่งและมีราคาหกในพันของ loss บนตารางนี้ยังใช้ได้
บน model จริงมักไม่ และแถวสุดท้ายคือทางแก้ที่รูปแบบไฟล์ทั้งหมดใช้

## 4. ไม้บรรทัดต่อกลุ่ม คือสิ่งที่รูปแบบไฟล์ต่างกัน

```python
def quantize_grouped(grid, bits=4, group=17):
    """Four bit with a scale per small group, which is what the GGUF and GPTQ families do."""
    flat = grid.reshape(-1, group)
    integers, scale = quantize(flat, bits)
    return integers.reshape(grid.shape), scale
```

ที่สี่บิตมีระดับให้ใช้แค่สิบห้า ไม้บรรทัดต่อแถวใช้ระดับส่วนใหญ่ไปกับตัวเลขใหญ่ไม่กี่ตัว และ
ตัวเลขเล็กที่เหลือทั้งแถวถูกปัดไปที่ศูนย์หรือหนึ่ง ดูสองบรรทัดสุดท้ายของการรัน

```text
the largest single error at 4 bits with a scale per row is 0.460
the largest number in the grid is 8.938
```

ตัวเลขใหญ่สุด 8.9 กำหนดขั้นของไม้บรรทัดที่ 1.3 ตัวเลขที่เล็กกว่า 0.6 ทั้งแถวกลายเป็นศูนย์
ไม้บรรทัดต่อกลุ่มเล็กๆ แก้ด้วยการให้แต่ละกลุ่มมีขั้นของตัวเอง ราคาคือไม้บรรทัดมากขึ้น ในตาราง
คือร้อยสามสิบหกไบต์ ผลคือ loss ลงจากหกในพันเหลือสามในพัน

นี่คือปุ่มที่รูปแบบไฟล์ต่างกัน GGUF ที่ llama.cpp ใช้ GPTQ และ AWQ ที่ vLLM ใช้ ทั้งหมดคือ
สี่บิตกับไม้บรรทัดต่อกลุ่มสามสิบสองหรือหกสิบสี่ ต่างกันที่วิธีเลือกไม้บรรทัด บางตัวดูข้อมูลจริง
ที่ไหลผ่านตอนเลือกเพื่อรักษาตัวเลขที่สำคัญ และ nf4 ที่ QLoRA ใช้วางสิบหกระดับไว้ตรงที่ตัวเลข
ของ model ที่ฝึกแล้วกระจุกตัวจริง แทนที่จะวางห่างเท่ากัน คุณไม่ต้องรู้รายละเอียดของแต่ละตัว
สิ่งที่ต้องรู้คือคำถามเดียวที่ทุกตัวตอบ ไม้บรรทัดกี่อัน วางยังไง

## 5. QLoRA คือบทที่ 18 บนฐานที่ปัดเศษแล้ว

บทที่ 18 บอกว่า LoRA ตรึงตารางเดิมและฝึกแค่คู่ตารางบาง ถ้าตารางเดิมถูกตรึงอยู่แล้ว มันไม่ต้อง
แม่นพอสำหรับ gradient ที่จะไหลเข้าไปในตัวมัน มันต้องแม่นพอแค่จะคูณ ซึ่งคือหัวข้อที่ 1 ผลคือ
เก็บฐานที่สี่บิต ฝึก adapter ที่สิบหกบิต และ model เจ็ดพันล้าน parameter ที่ต้องการการ์ดสี่สิบ
กิกะไบต์สำหรับ LoRA ธรรมดา เหลือสิบ

วิธีนี้ชื่อ QLoRA (quantized LoRA คือการฝึก LoRA adapter บน model ฐานที่เก็บไว้ที่สี่บิต) และ
`load_4bit.py` ในโฟลเดอร์เดียวกันทำมัน โหลด model ด้วย nf4 พร้อมไม้บรรทัดต่อกลุ่มหกสิบสี่
รายงานหน่วยความจำเทียบกับสิบหกบิต และด้วย `--train` ใส่ adapter จากบทที่ 18 ซ้อนข้างบน
บรรทัดเดียวที่ต่างจาก script ของบทที่ 18 นอกจากการโหลดคือ `prepare_model_for_kbit_training`
ซึ่งเก็บชั้นไม่กี่ชั้นที่ต้องแม่นไว้ที่ความละเอียดเต็ม คือ layer norm จากบทพื้นฐานที่ 6 และ
ตารางที่แปลง token สุดท้ายเป็นคะแนน เพื่อให้ gradient ไหลผ่านฐานที่หยาบไปถึง adapter โดย
ไม่ถูกความหยาบกลืน

ต้องมี GPU ต้องเป็น Linux เพราะ library ที่ทำสี่บิตรองรับแค่นั้น และไม่ได้รันใน CI สิ่งที่ CI
รันคือตารางในหัวข้อที่ 3 ซึ่งคือกลไกเดียวกันบนของที่นับได้ครับ

## 6. สรุป

- หลังฝึกเสร็จตัวเลขแค่ถูกคูณ และการคูณทนความหยาบได้

- absmax คือไม้บรรทัดต่อแถว แปดบิตฟรี สี่บิตมีราคาที่วัดได้

- QLoRA คือ LoRA บนฐานสี่บิต เพราะฐานที่ตรึงไว้ไม่ต้องแม่นพอสำหรับ gradient
