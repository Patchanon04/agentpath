# บทพื้นฐานที่ 2 token คือหน่วยที่คิดเงิน

ประโยคเดียวกัน agent อ่านไฟล์ ยาวสามสิบ byte tokenizer ตัวหนึ่งบอกว่ามันคือยี่สิบห้า
token อีกตัวบอกว่าเก้า ทั้งสองตัวเขียนด้วยโค้ดเดียวกันทุกบรรทัด ต่างกันแค่ข้อความที่
มันเคยเห็นตอนถูกสร้าง และถ้าคุณจ่ายเงินตาม token ความต่างนั้นคือเกือบสามเท่าของ
บิล

บทที่แล้วจบตรงที่ model ไม่รับ byte ตรงๆ บทนี้สร้างสิ่งที่มันรับจริงขึ้นมาจากศูนย์
ประมาณเจ็ดสิบบรรทัด แล้วใช้มันอธิบายว่าทำไมภาษาไทยถึงแพง และแพงเพราะอะไรกันแน่
เพราะคำตอบไม่ใช่สิ่งที่คนส่วนใหญ่คิด

หัวข้อที่ 3 เรื่องลำดับของการ encode ข้ามได้ในรอบแรก มันสำคัญกับคนที่จะเขียน
tokenizer เอง ไม่ใช่กับคนที่จะเรียกใช้

## 1. token อยู่ระหว่าง byte กับคำ

เหตุผลที่ model ไม่ใช้ byte เป็นหน่วย คือ byte ละเอียดเกินไป คำว่า สวัสดี เป็น
สิบแปดหน่วย และรูปแบบที่ model ต้องเรียนรู้จะกระจายอยู่บนหน่วยที่แต่ละหน่วยแทบ
ไม่มีความหมาย มันเรียนได้ แต่ช้าและแพงกว่าที่ควร

เหตุผลที่ไม่ใช้คำเป็นหน่วย ตรงข้ามกัน คำหยาบเกินไป ภาษามีคำไม่รู้จบ ชื่อคน ชื่อ
ยา คำผิด คำใหม่ที่เพิ่งเกิดเมื่อวาน ถ้าหน่วยคือคำ คำที่ไม่เคยเห็นตอนฝึกจะไม่มี
เลขให้เลย และ model จะตอบไม่ได้ทั้งที่รู้ทุกอย่างรอบข้าง

token (โทเคน คือชิ้นส่วนของข้อความที่ model ใช้เป็นหน่วย มักเป็นบางส่วนของคำ)
อยู่ตรงกลาง คำที่พบบ่อยเป็น token เดียว คำที่พบน้อยแตกเป็นหลาย token ที่ประกอบ
จากชิ้นที่พบบ่อย และในกรณีเลวร้ายที่สุด ทุกอย่างยังแตกกลับไปเป็น byte ได้เสมอ จึง
ไม่มีข้อความไหนที่แทนไม่ได้

ก่อน subword จะชนะ การแบ่งระดับคำเคยเป็นวิธีปกติ ภาษาอังกฤษแบ่งที่ช่องว่างแล้วจบ
ภาษาไทยไม่มีช่องว่างระหว่างคำ การแบ่งระดับคำจึงต้องมีอัลกอริทึมหรือ model อีกตัวมา
เดาว่าคำจบตรงไหน ตากลม คือ ตา กลม หรือ ตาก ลม ต้องรู้บริบทถึงจะตอบได้ และตัวตัดคำ
ทุกตัวผิดบ้าง งานตัดคำไทยเป็นสาขาย่อยของตัวเองด้วยเหตุผลนี้ tokenizer ระดับ byte ที่
บทนี้สร้างไม่ต้องรู้เลยว่าคำคืออะไร มันเลี่ยงปัญหานั้นทั้งก้อน ราคาที่จ่ายคือ token ของ
ภาษาไทยไม่ตรงกับคำ และหัวข้อที่ 5 จะให้เห็นว่ามันตัดกลางตัวอักษรได้ด้วยซ้ำ

คำถามคือใครตัดสินว่าชิ้นไหนพบบ่อย คำตอบคือไม่มีใคร มันถูกนับ

## 2. อัลกอริทึมมีสองบรรทัดที่สำคัญ

byte pair encoding (การเข้ารหัสคู่ byte หรือ BPE คือวิธีสร้าง token ด้วยการรวมคู่
ที่พบบ่อยที่สุดซ้ำๆ) เริ่มจากข้อความที่เป็น byte แล้วทำสองอย่างสลับกันไป นับว่าคู่
ไหนที่อยู่ติดกันพบบ่อยที่สุด แล้วแทนคู่นั้นทั้งหมดด้วยเลขใหม่หนึ่งตัว

การนับคือหนึ่งบรรทัด

```python
def pair_counts(ids):
    """How often each adjacent pair occurs in a list of ids."""
    return Counter(zip(ids, ids[1:], strict=False))
```

การแทนที่คือ loop เดียว

```python
def merge(ids, pair, new_id):
    """Replace every occurrence of pair in ids with new_id."""
    out = []
    i = 0
    while i < len(ids):
        if i + 1 < len(ids) and (ids[i], ids[i + 1]) == pair:
            out.append(new_id)
            i += 2
        else:
            out.append(ids[i])
            i += 1
    return out
```

เดินไปทีละตำแหน่ง ถ้าตำแหน่งนี้กับตำแหน่งถัดไปคือคู่ที่ต้องการ ใส่เลขใหม่แล้ว
กระโดดข้ามสองช่อง ถ้าไม่ใช่ เก็บตัวเดิมแล้วเดินหนึ่งช่อง ไม่มีอะไรมากกว่านั้น

การฝึกคือการทำสองอย่างนี้วนจนกว่าจะได้จำนวน token ที่ต้องการ

```python
def train(text, vocabulary_size):
    """Learn merges from text until the vocabulary is the size asked for."""
    ids = list(text.encode("utf-8"))
    merges = {}
    for new_id in range(256, vocabulary_size):
        counts = pair_counts(ids)
        if not counts:
            break
        pair = max(counts, key=counts.get)
        if counts[pair] < 2:
            break
        ids = merge(ids, pair, new_id)
        merges[pair] = new_id
    return merges
```

เลข 256 ไม่ใช่ตัวเลขลอยๆ byte มีค่าได้ 256 แบบ และทั้ง 256 แบบเป็น token ตั้งแต่
ก่อนจะเรียนรู้อะไร นั่นคือสิ่งที่รับประกันว่าทุกข้อความแทนได้ การเรียนรู้แต่ละ
ครั้งเพิ่ม token ใหม่หนึ่งตัวถัดจากนั้น vocabulary ขนาด 300 จึงแปลว่ารวมคู่ได้
อย่างมาก 44 ครั้ง model จริงมี vocabulary ราวแสนถึงสองแสน ซึ่งคือ loop เดียวกัน
นี้วนแสนรอบบนข้อความขนาดอินเทอร์เน็ตครับ

## 3. ลำดับที่เรียนรู้คือลำดับที่ต้องใช้

การ encode ข้อความใหม่ทำซ้ำการรวมคู่ทุกอันตามลำดับเดิมที่เรียนรู้มา

```python
def encode(text, merges):
    """Text to ids, applying the merges in the order they were learned."""
    ids = list(text.encode("utf-8"))
    for pair, new_id in merges.items():
        ids = merge(ids, pair, new_id)
    return ids
```

ลำดับสำคัญ เพราะการรวมครั้งหลังอาจสร้างขึ้นจากผลของการรวมครั้งก่อน ถ้าคู่ที่สิบ
คือ (คู่ที่สาม, คู่ที่เจ็ด) การเอาคู่ที่สิบไปใช้ก่อนคู่ที่สามจะไม่มีวันเจออะไรให้รวม
dict ของ Python รักษาลำดับที่ใส่เข้าไป และ `train` ใส่ตามลำดับที่เรียนรู้ นั่นคือ
เหตุผลทั้งหมดที่ `merges` เป็น dict

## 4. ราคาของภาษาไทย และเหตุผลจริงของมัน

ทีนี้การทดลอง ไฟล์นี้มี corpus (คลังข้อความ คือข้อความที่ใช้ฝึก) เล็กๆ สองชุด
อังกฤษหนึ่งย่อหน้า ไทยหนึ่งย่อหน้า ฝึก tokenizer สองตัว ตัวแรกเห็นแต่อังกฤษ ตัวที่
สองเห็นทั้งคู่ แล้วเอาประโยคเดียวกันไป encode ทั้งสองตัว

```text
== trained on English only, 44 merges ==
  'the agent reads the file'  24 bytes  7 tokens
  'agent อ่านไฟล์'  30 bytes  25 tokens

== trained on both, 44 merges ==
  'the agent reads the file'  24 bytes  9 tokens
  'agent อ่านไฟล์'  30 bytes  9 tokens
```

tokenizer ที่ไม่เคยเห็นภาษาไทยจ่าย token ให้เกือบทุก byte ของมัน ยี่สิบห้า token
สำหรับประโยคที่อังกฤษจ่ายเจ็ด ไม่ใช่เพราะภาษาไทยซับซ้อน แต่เพราะไม่มีคู่ byte
ไทยคู่ไหนเคยถูกนับว่าพบบ่อย จึงไม่มีคู่ไหนถูกรวม ทุก byte ยืนเดี่ยว

พอให้มันเห็นภาษาไทยหนึ่งย่อหน้า ประโยคเดียวกันเหลือเก้า เท่ากับอังกฤษพอดี

นี่คือประเด็นที่บทนี้อยากให้จำ ราคาของภาษาไม่ใช่คุณสมบัติของภาษา มันคือคุณสมบัติ
ของสิ่งที่ tokenizer ถูกฝึกมา และ tokenizer เบื้องหลัง model ที่คุณจะเรียกในหนังสือ
เล่มนี้ถูกฝึกจากข้อความที่เป็นอังกฤษเป็นส่วนใหญ่ ภาษาไทยจึงจ่ายมากกว่า ไม่ใช่สาม
เท่าแบบชั้น byte แต่มากกว่าแน่นอน และบทที่ 15 ของหนังสือเล่มนี้ว่าด้วยการอยู่กับ
ความจริงข้อนั้น

สังเกตว่าอังกฤษแพงขึ้นเล็กน้อยเมื่อ tokenizer ต้องแบ่งการรวม 44 ครั้งให้สองภาษา
เจ็ดกลายเป็นเก้า vocabulary มีที่จำกัด และทุกภาษาที่เพิ่มเข้ามาแย่งที่นั้นครับ

## 5. token ตัดกลางตัวอักษรได้

ดูชิ้นส่วนที่ tokenizer ตัวที่สองสร้างจากประโยคไทย

```text
['a', 'gent ', 'อ่า', '<e0 b8 99 e0 b9>', '<84 e0 b8>', '<9f>', 'ล', '<e0 b9>', '<8c>']
```

ชิ้นในวงเล็บแหลมคือ token ที่แสดงเป็นข้อความไม่ได้ เพราะมันจบกลางตัวอักษร ตัว น
คือสาม byte e0 b8 99 และ token หนึ่งเก็บ e0 b8 99 e0 b9 ซึ่งคือ น ทั้งตัวกับสอง
ในสาม byte ของตัวถัดไป

```python
def pieces(ids, merges):
    """Each id as readable text, or as its bytes when it is not whole text."""
    table = vocabulary(merges)
    shown = []
    for i in ids:
        try:
            shown.append(table[i].decode("utf-8"))
        except UnicodeDecodeError:
            shown.append("<" + " ".join(f"{b:02x}" for b in table[i]) + ">")
    return shown
```

เรื่องนี้เกิดขึ้นเพราะอัลกอริทึมทำงานกับ byte และไม่รู้เลยว่าตัวอักษรคืออะไร มัน
เห็นแค่คู่ที่พบบ่อย และคู่ที่พบบ่อยในภาษาไทยมักเป็นครึ่งหลังของตัวอักษรหนึ่งกับ
ครึ่งแรกของตัวถัดไป เพราะตัวอักษรไทยทุกตัวขึ้นต้นด้วย e0 เหมือนกันหมด

สำหรับคนเรียกใช้ model เรื่องนี้แปลว่าสองอย่าง จำนวน token ของข้อความไทยเดาจาก
จำนวนตัวอักษรไม่ได้ และเครื่องมือที่นับ token ให้ ซึ่งบทที่ 1 หัวข้อ 4 พูดถึง ต้อง
เป็นตัวเดียวกับที่ model ใช้จริง ไม่ใช่ตัวที่ใกล้เคียง

### 5.1 ตระกูลของ tokenizer และเหตุผลที่ตัวนี้ทำงานบน byte

BPE ที่บทนี้สร้างไม่ใช่ตัวเดียวที่มี model card ของ model ที่คุณเรียกจะบอกชื่อหนึ่งในสี่
ตระกูล และความต่างของมันอยู่ที่สองคำถาม เริ่มจากอะไร และรวมด้วยกฎอะไร

WordPiece (เวิร์ดพีซ คือ tokenizer ตระกูล BERT ที่รวมคู่ซึ่งเพิ่มความน่าจะเป็นของข้อความ
มากที่สุด แทนที่จะรวมคู่ที่พบบ่อยที่สุด) เริ่มจากตัวอักษรแทน byte และเลือกคู่ที่จะรวมด้วย
คำถามว่าคู่ไหนทำให้ข้อความทั้งหมดน่าจะเป็นมากขึ้น ไม่ใช่คู่ไหนพบบ่อย ผลลัพธ์หน้าตาคล้าย
กัน แต่ชิ้นที่ต่อจากชิ้นแรกของคำจะมีเครื่องหมายนำหน้าให้รู้ว่ามันคือกลางคำ

SentencePiece (เซนเทนซ์พีซ คือ tokenizer ที่มองช่องว่างเป็นตัวอักษรธรรมดา จึงไม่ต้อง
ตัดคำก่อน) แก้ปัญหาที่หัวข้อที่ 1 พูดถึง คือภาษาที่ไม่มีช่องว่าง มันไม่ตัดที่ช่องว่างเลย
มันมองช่องว่างเป็นตัวอักษรตัวหนึ่งที่มีสถานะเท่ากับตัวอื่น แล้วให้ BPE หรือวิธีอื่นทำงาน
บนข้อความดิบทั้งก้อน ภาษาไทย ญี่ปุ่น จีน ได้ประโยชน์จากมันโดยตรง

byte-level BPE (บีพีอีระดับไบต์ คือ BPE ที่เริ่มจาก 256 byte แทนที่จะเริ่มจากตัวอักษร) คือ
สิ่งที่ไฟล์ของบทนี้เป็น และคือสิ่งที่ตระกูล GPT ใช้ ข้อดีเดียวที่ทำให้มันชนะคือหัวข้อที่ 2
พูดไว้ ทุกข้อความแทนได้เสมอ ไม่มี token ชื่อ unknown เพราะกรณีเลวร้ายที่สุดคือ
byte เปล่าๆ tokenizer ที่เริ่มจากตัวอักษรต้องมีรายการตัวอักษรที่รู้จัก และตัวอักษรที่ไม่
อยู่ในรายการ เช่นอีโมจิใหม่หรือตัวอักษรของภาษาที่ไม่ได้เตรียมไว้ จะกลายเป็น unknown
ทั้งตัว ราคาของ byte-level คือหัวข้อนี้ทั้งหัวข้อ token ตัดกลางตัวอักษรได้

ตระกูลที่สี่คือไม่มี tokenizer เลย ป้อน byte ตรงๆ ให้ model ซึ่งมีคนทดลองและได้ผล แต่
ยังจ่ายราคาที่หัวข้อที่ 1 บอกไว้ คือลำดับยาวขึ้นสามถึงสี่เท่า และบทถัดไปจะให้เห็นว่าความ
ยาวของลำดับคือสิ่งที่แพงที่สุดใน model ทั้งตัว

สิ่งที่ควรออกจากหัวข้อนี้ไม่ใช่ชื่อทั้งสี่ แต่คือคำถามเดียวที่ควรถามเมื่อเจอ tokenizer ตัว
ใหม่ มันเริ่มจากอะไร และมันทำอะไรกับสิ่งที่ไม่เคยเห็น สองคำตอบนั้นบอกได้ว่าภาษาของคุณ
จะแพงแค่ไหน และจะพังยังไงครับ

## 6. สรุป

- token คือหน่วยระหว่าง byte กับคำ ถูกสร้างจากการนับ ไม่ใช่จากกฎ

- BPE คือสองบรรทัด นับคู่ที่พบบ่อยที่สุด แล้วแทนด้วยเลขใหม่ วนจนได้ขนาดที่ต้องการ

- 256 token แรกคือ byte ทุกข้อความจึงแทนได้เสมอ

- ราคาของภาษาขึ้นกับสิ่งที่ tokenizer เคยเห็น ไม่ใช่ตัวภาษา และ tokenizer จริง
  เห็นอังกฤษเป็นหลัก

- token ตัดกลางตัวอักษรได้ จำนวน token ของภาษาไทยจึงต้องนับด้วย tokenizer ตัวจริง

- tokenizer มีสี่ตระกูล ต่างกันที่เริ่มจากอะไรและทำอะไรกับสิ่งที่ไม่เคยเห็น byte-level
  ชนะเพราะไม่มีคำว่า unknown
