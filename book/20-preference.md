พอดี และสิ่งที่เหลือคือการโยนเหรียญ ถ้า trainer เฉลี่ยหลายก้าวก่อนพิมพ์ ตัวเลขแรกที่คุณเห็น

ของคน บทนี้ทำรอบนั้นบนตารางของบทพื้นฐานที่ 4 ด้วยวิธีที่ใช้กันจริงตั้งแต่ปี 2023 ซึ่งตัดส่วน
ที่ยากที่สุดของวิธีเดิมทิ้งไปทั้งก้อน

## 1. ข้อมูลของรอบนี้คือคู่ ไม่ใช่คำตอบ

instruction tuning ในบทที่ 17 ใช้คู่คำขอกับคำตอบที่ดี การปรับตามความชอบใช้สามอย่าง คำขอ
คำตอบที่คนเลือก และคำตอบที่คนไม่เลือก ไม่มีใครบอกว่าคำตอบที่เลือกดีแค่ไหน แค่ว่าดีกว่าอีก
อัน นั่นคือสิ่งที่คนให้ได้อย่างสม่ำเสมอ การให้คะแนนคำตอบเดี่ยวๆ จากหนึ่งถึงสิบ คนสองคนให้
ต่างกัน การเลือกระหว่างสองอัน คนส่วนใหญ่เลือกตรงกัน

เอาคำตอบเดียวไปให้คนห้าคนให้คะแนนเต็มสิบ แล้วคุณจะได้สี่ หก หก เจ็ด และเก้า ไม่มีใครผิด
พวกเขาแค่ตั้งเส้นคนละที่ วางคำตอบสองอันข้างกันแล้วถามว่าชอบอันไหนมากกว่า สี่ในห้าชี้อันเดียว
กัน ข้อมูลของรอบนี้จึงเป็นคู่ ไม่ใช่คะแนน

ในไฟล์ของบทนี้ความชอบคือคู่ของคำถัดไปสามคู่ เช่น หลัง `agent` คนชอบ `asks`
มากกว่า `runs` หลัง `tool` ชอบ `returns` มากกว่า `and` และ model ฐานไม่เคยเห็น
`asks` ตามหลัง `agent` เลย นี่จึงเป็นความชอบที่มันต้องเรียนสวนนิสัยตัวเอง

## 2. วิธีเดิมต้องการ model อีกตัว และวิธีใหม่ไม่ต้อง

RLHF ตามที่บทพื้นฐานที่ 7 เรียกชื่อ ทำสองขั้น ขั้นแรกฝึก reward model (model อีกตัวที่เรี
ยนจากคู่ความชอบ แล้วให้คะแนนคำตอบได้) ขั้นสองใช้ reinforcement learning (การเรียนรู้แบบเส
ริมกำลัง คือปรับ model ให้ตอบแบบที่ได้คะแนนสูง) ปรับ model หลักให้ได้คะแนนสูงจากตัวแร
ก ทั้งสองขั้นยาก ขั้นที่สองต้องถือ model สี่ตัวในหน่วยความจำพร้อมกัน และไม่เสถียรจนต้องมี
คนเชี่ยวชาญนั่งเฝ้า

คำว่าไม่เสถียรมีหน้าตาแบบนี้ กราฟคะแนนไต่ขึ้นสวยงามทุกชั่วโมง แล้วคุณเปิดดูคำตอบ
จริง แล้วพบว่า model
ค้นพบว่าการขึ้นต้นทุกคำตอบด้วยประโยคขอบคุณที่ยาวสามบรรทัด ได้คะแนนสูงเสมอ มันจึง
ทำแบบนั้นกับทุกคำถาม ตัวให้คะแนนพอใจมาก ส่วนคนอ่านไม่

ปี 2023 มีบทความที่แสดงว่าถ้าเขียนเป้าหมายของทั้งสองขั้นออกมาเป็นคณิตศาสตร์ reward model
ที่ดีที่สุดคือฟังก์ชันของความน่าจะเป็นของ model หลักเอง เทียบกับ model อ้างอิง แปลว่าแทน
ที่จะฝึกตัวให้คะแนนแล้วค่อยฝึก model ให้เอาใจมัน ฝึก model บนคู่ความชอบตรงๆ ได้เลยด้วย
loss ตัวเดียว วิธีนี้ชื่อ DPO (direct preference optimization คือปรับ model ตามคู่ความชอบ
ตรงๆ ไม่ต้องมี reward model) และมันคือสิ่งที่คนส่วนใหญ่รันในวันนี้

ความต่างวัดได้จากสิ่งที่ต้องเตรียม ทางเดิมคือฝึก model ให้คะแนนหนึ่งตัว ตั้งลูปที่ถือ model
สี่ตัว แล้วมีคนคอยดูว่ามันไม่หลุด ทางใหม่คือไฟล์ที่แต่ละบรรทัดมีสามช่อง กับ script เดียวที่
รันข้ามคืนบนการ์ดใบเดียว

## 3. loss ในสิบบรรทัด

loss ทั้งตัวคือฟังก์ชันเดียวที่อ่านทีละคู่ และนี่คือมัน

```python
def dpo_loss(weights, reference, preferences, index, beta=1.0):
    """How far the policy is from preferring chosen over rejected, relative to the reference."""
    total = 0.0
    for context, chosen, rejected in preferences:
        policy_margin = log_probability(weights, context, chosen, index) - log_probability(
            weights, context, rejected, index
        )
        reference_margin = log_probability(reference, context, chosen, index) - log_probability(
            reference, context, rejected, index
        )
        total += -np.log(sigmoid(beta * (policy_margin - reference_margin)))
    return total / len(preferences)
```

อ่านทีละคู่ policy (model ที่กำลังถูกฝึก) ชอบ chosen มากกว่า rejected เท่าไหร่เป็น log ขอ
งอัตราส่วน ค่านั้นเรียกว่า margin (ผลต่างของ log ความน่าจะเป็นระหว่างสองคำตอบ) reference
(สำเนา model ก่อนฝึกที่ตรึงไว้ตลอด) มี margin ของตัวเองอยู่แล้ว เอามาลบกัน คูณด้วย beta
ผ่าน sigmoid (ฟังก์ชันที่บีบตัวเลขให้อยู่ระหว่างศูนย์กับหนึ่ง) แล้วเอาลบ log

พจน์ reference คือหัวใจ ถ้าไม่มีมัน ทางที่ง่ายที่สุดในการกด loss ให้ต่ำคือให้คำที่ถูกปฏิเสธ
ทุกคำเป็นไปไม่ได้ และนั่นทำลาย model ที่เหลือทั้งตัว ถ้าคู่หนึ่งบอกว่าไม่ชอบคำว่า `and` ตาม
หลัง `tool` ทางที่ง่ายที่สุดคือกดความน่าจะเป็นของ `and` ให้เกือบศูนย์ทุกที่ที่มันโผล่ แล้ว
model ก็เขียนประโยคภาษาอังกฤษไม่ได้อีกเลย ทั้งที่ loss ของคู่นั้นสวยมาก การลบ margin ของ
reference ออกแปลว่า
model ได้รางวัลเฉพาะจากการขยับความชอบเทียบกับจุดที่มันเริ่ม ไม่ใช่จากความชอบสัมบูรณ์ และ
beta (ตัวคูณที่บอกว่า policy จะโดนลงโทษแรงแค่ไหนเมื่อห่างจาก reference) คือความ
ยาวของสายจูง

ตอนเริ่ม policy กับ reference คือตัวเดียวกัน margin ทั้งสองจึงเท่ากัน
ผลต่างเป็นศูนย์ sigmoid ของศูนย์คือครึ่ง
และลบ log ครึ่งคือ log สอง 0.693 ตอนเปิดบทมาจากตรงนี้ และ `check.py` ยืนยันว่ามันเท่ากับ
log สองถึงทศนิยมตำแหน่งที่เก้า

## 4. ตัวเลขที่ได้

```text
dpo loss at the start 0.693, after training 0.013

after 'the agent'   reference   tuned
  asks              0.000    0.003
  runs              0.121    0.015
  reads             0.496    0.554
  decides           0.371    0.415

mean change in every probability of the model 0.0015
the same with plain finetuning on the chosen words only 0.0043
```

อ่านแถว runs คำที่ถูกปฏิเสธตกจาก 0.121 เหลือ 0.015 ส่วน asks ที่ถูกเลือกขึ้นจากศูนย์มาที่
0.003 เท่านั้น เพราะ model ฐานไม่เคยเห็น asks ตามหลัง agent และการขยับหกสิบก้าวพาคำหนึ่ง
จากศูนย์ไปได้แค่นั้น ความน่าจะเป็นที่หายไปจาก runs ไปอยู่ที่ reads กับ decides แทน

นี่คือสิ่งที่ควรเข้าใจเกี่ยวกับการปรับตามความชอบบน model จริง มันดันคำตอบที่ถูกปฏิเสธลงได้
ง่ายกว่าดึงคำตอบที่ถูกเลือกขึ้นมาก และผลส่วนใหญ่แสดงออกในสิ่งที่ model เลิกทำ เลิกตอบยาว
เกิน เลิกแต่งข้อเท็จจริง เลิกทำตามคำสั่งที่อยู่ในไฟล์ที่มันอ่าน สิ่งที่คนเรียกว่าบุคลิกในบท
พื้นฐานที่ 7 ส่วนใหญ่คือรายการของสิ่งที่ถูกดันลง

สองบรรทัดสุดท้ายคือพจน์ reference ทำงาน DPO ขยับความน่าจะเป็นทั้ง model โดยเฉลี่ย
0.0015 fine-tune ธรรมดาบนคู่คำที่ถูกเลือกสามคู่เดียวกัน ก้าวเท่ากัน อัตราเท่ากัน ขยับสามเท่า
ของนั้น สายจูงทำงาน และมันคือความต่างระหว่าง model ที่เรียนความชอบข้อหนึ่ง กับ model ที่
ลืมทุกอย่างอื่นเพื่อสนองมัน

## 5. script จริง และค่า beta ที่ต่างกันสิบเท่า

`train_dpo.py` คือ loss เดียวกันบน model แบบเปิด trl ถือ reference ถือ loop และอ่านไฟล์
ที่แต่ละบรรทัดมีคำขอ คำตอบที่เลือก และคำตอบที่ปฏิเสธ จุดเริ่มปกติคือ adapter จากบทที่ 18
ที่ merge แล้ว เพราะรอบที่สามมาหลังรอบที่สอง

สองอย่างใน script ที่ต่างจากไฟล์ numpy และมีเหตุผล beta
เป็นหนึ่งในสิบแทนที่จะเป็นหนึ่งเพราะ log
ความน่าจะเป็นของคำตอบจริงคือผลรวมของหลายร้อย token และ margin
จึงใหญ่กว่าตามไปด้วย และ learning rate ต่ำกว่าบทที่ 18 สี่เท่า adapter
ยังเริ่มจากศูนย์ นั่นคือเหตุผลให้ใช้อัตราสูง แต่นี่คือการขยับ model
ที่ทำงานได้แล้ว ไม่ใช่การสอนจากศูนย์ นั่นคือเหตุผลให้ต่ำลง ส่วนที่ทำให้ DPO กับ
LoRA เข้ากันได้ดีคือ reference ไม่ต้องเป็นสำเนาที่สอง มันคือ weight เดิมที่ปิด
adapter trl จัดการเรื่องนี้ให้เมื่อ `ref_model` เป็น None และนั่นคือเหตุผลที่
DPO ทำได้บนการ์ดที่ RLHF ไม่มีวันพอครับ

## 6. สรุป

- ข้อมูลของรอบนี้คือคู่ คำตอบที่ดีกว่ากับที่แย่กว่า เพราะคนเลือกได้ตรงกันมากกว่าให้คะแนน

- RLHF ต้องการ reward model กับ reinforcement learning DPO เขียนทั้งสองเป็น loss เดียว
  บนความน่าจะเป็นของ model เอง

- reference คือสายจูง beta คือความยาว และ loss ก้าวแรกคือ log สองเสมอ

- ผลส่วนใหญ่อยู่ในสิ่งที่ model เลิกทำ ไม่ใช่สิ่งที่มันเริ่มทำ
